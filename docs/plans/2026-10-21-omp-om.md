# omp-om Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fork Pi OM (`pi-observational-memory` 3.1.4) into an omp plugin whose compaction hook always renders the ledger as the summary, so omp makes no summary LLM call.

**Architecture:** Copy Pi OM's `src/`, `tests/`, `scripts/` into this directory and keep its `@earendil-works/*` imports (omp's loader rewrites them onto host copies). Change only what the design lists: one `model` key in `omp-om.json`, no `agent_settled` trigger, no `worker-stream.ts`, `om_recall` tool name, a compaction hook that never declines and has a 20s catch-up deadline with a warning, and `reset_boundary` handling.

**Tech Stack:** TypeScript (ESM), vitest, esbuild (`scripts/build.js` produces `dist/index.ts`), omp extension API.

**Spec:** `docs/specs/2026-10-21-omp-om-design.md`

## Global Constraints

- Source of the fork: `/Users/sovorn/tmp/pom-clone/repo` (Pi OM 3.1.4, commit `022da5e`), MIT. Keep `LICENSE` and add attribution to the original authors.
- Config file: `~/.omp/agent/omp-om.json` (via `getAgentDir()`), optional `<cwd>/.omp/omp-om.json` merged over it. ONE `model` key, no per-worker overrides. Default `"@smol"`. Accepts `provider/id[:thinking]`, bare id, or `@role`, resolved with `ctx.models.resolve`.
- Defaults kept from Pi OM: `observeAfterTokens: 10_000`, `reflectAfterTokens: 20_000`, `compactionCatchUpMaxChunks: 2`.
- Removed from config: `compactAfterTokens`, `compactAfterTokensMode`, `compactAfterTokensRatio`, `consolidateWhenIdle`.
- Tool `recall` is renamed `om_recall`.
- Hook catch-up deadline: 20_000 ms (constant in code, not configurable). omp aborts handlers at 30s.
- The hook never returns `undefined` and never throws. Missing/unresolvable model, timeout, or observer not reaching the cut: skip observe/reflect, show a warning when `ctx.hasUI`, render ledger so far.
- The plugin never edits user settings (`~/.omp/agent/config.yml`) and never writes outside `<cwd>`'s session and `omp-om.json` reads.
- `om.*` marker entries stay `custom` entries with `data.coversUpToId` (format unchanged from Pi OM).
- Smoke runs use `omp -e <path>` from a scratch cwd, never the user's real session or `~/.omp` config.

## Review Focus

- First compaction in a session: zero ledger, model unset. Summary is non-empty and deterministic, a warning names the cause.
- Observer call hangs past 20s inside the hook. Hook returns a compaction by ~20s, with a warning.
- `event.signal` aborts mid catch-up. No throw; hook returns `{ cancel: true }` [call].
- Malformed or unknown-key `omp-om.json`. Defaults used, warning shown, no crash.
- `/clear` then compaction. Entries before the latest `reset_boundary` do not appear in the summary or count toward catch-up.
- One ledger record larger than the summary budget. It is truncated into the summary instead of leaving the summary empty.
